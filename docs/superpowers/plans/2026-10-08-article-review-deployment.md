# 内容审核与排期分离：部署及历史数据说明

日期：2026-10-08。用户确认敏感内容进入待审核后，定时到期也必须先审批。本轮没有部署、连接真实业务数据库或调用真实审核/搜索服务。

## 状态模型

仍使用既有前端状态码 0–4。新增服务器管理的 review_state 作为当前内容的许可，不接受客户端授予：

| review_state | 含义 | 到期能否由定时任务发布 |
|---|---|---|
| UNVERIFIED | 历史来源/校验许可无法确认 | 否 |
| REQUIRED | 需要人工审核，或者旧批准已失效 | 否 |
| CLEARED | 新内容通过现有敏感词检查且未有人工审核挂起 | 可以，但还必须满足待发布/到期/未删除 |
| APPROVED | 管理员明确批准当前内容 | 可以，但到期前仍不能发布 |

自动检查放行不是人工批准。时间不授予许可；PENDING 外观相同不代表内部含义相同。ArticleVO/DetailVO 附加 reviewState 元数据，前端没有修改。既有前端若仍把所有状态 1 显示为待审核，需要未来展示调整；审核队列已过滤已许可、仅等待日期的条目。

## 入口一致性

- 创建：安全的立即提交按旧规则公开，未来排期先等待；敏感内容待审。
- 草稿提交：已知安全的新草稿可以按排期等待，REQUIRED/UNVERIFIED 不能被提交或改排期放行。
- 编辑：已有审核挂起不会因去掉一个词被静默清除；人工批准后的内容/摘要/封面/分类变更使批准失效。元数据-only 修改不抹除原有标题/正文，也不把它当作新批准。
- 两个管理员入口使用同一批准判断和行锁，保留未来日期；到期/无未来日期的批准可立即公开。审查通知不能把尚在等待日期的内容说成已经发布。
- 撤销公开许可后，文章及关联图片索引删除在提交后安排；两套审核入口接入共同发布/缓存效果。
- 检测与过滤抛错时返回不可用、事务不保存内容，不把检查失败当作安全。
- 内容写入、审批、草稿提交以及相关整行变更在同一文章行上序列化；定时 SQL 再检查最新许可与日期。条件写失败不发送成功效果。

本阶段审批粒度是当前文章记录的内容，不是增加一个历史版本系统；不自动重写过去已公开的正文或审核操作日志。驳回再提交、审批重复请求及更完整的保留/归档策略仍待独立业务设计。

## 必须先迁移再部署

新数据库初始化的两个活动 schema 定义已包含：

```sql
review_state VARCHAR(16) NOT NULL DEFAULT 'UNVERIFIED'
```

已有数据库必须先备份、盘点并一次性执行：

`D:\zhixun\db\migrations\2026-10-08-article-review-state.sql`

只读列检查：

```sql
SELECT COLUMN_NAME
FROM INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'cms_article' AND COLUMN_NAME = 'review_state';
```

列已存在时不要重复 ADD COLUMN，确认其类型、非空及默认值。CREATE TABLE IF NOT EXISTS 不会为旧表补列。

**没有把这项改动挂进旧迁移执行器。** 现有 DatabaseMigrationRunner 只维护历史显式列表，以最大版本跳过已执行版本，并在异常后继续启动；还有未注册历史脚本。本轮不顺手修改该基础设施、执行未知历史脚本或错误推进版本号。此迁移须作为明确的 schema-first 操作独立管理；仅放 SQL 文件或重启不能证明已迁移。

## 历史数据原则与切换

新增列默认给所有原记录 UNVERIFIED，而不是根据发布时间、PUBLISHED 或历史日志猜测当前内容已经批准。原已公开内容不批量下线，但新的发布/审批/编辑动作会使用新许可规则；原待审/待定时内容没有许可不能被自动发布。

切换前停掉旧定时任务并暂停相关写入，完成隔离验证/备份与加列，再让所有实例切换新规则。不能让旧二进制在混合部署期间继续无许可发布 PENDING。

要恢复旧排期，须确认当前内容和可信审核来源，并进行当前版本人工批准或受控重新审核；本轮不提供伪造批准回填。旧公开内容的后续编辑也不能因为旧状态就继承许可。

回滚保留新增列和已保存许可，不删除数据。旧版本不认识许可门槛，切回旧版本会恢复旧绕过风险，不是无损业务回滚，必须停止发布任务并另行评估。

## 生产与未完成边界

测试使用 Mockito 和隔离 H2 + 真实 MyBatis/事务代理，覆盖旧数据默认、当前内容批准与并发编辑、到期规则及效果。H2 不替代目标 MySQL 的行锁、驱动类型、数据库部署和多角色端到端验证。

外部搜索/缓存/消息依旧不是可靠 outbox；依赖失败、事件乱序和重启补偿仍未全面重构。输入事实/图像内容的审核范围、完整作者重提审 UX 及前端状态展示仍待后续。
